# Web Console 使用说明

Web Console 是 Polaris 的主要操作界面。

如果你平时主要通过浏览器查看请求、保存请求、管理模拟规则和调整服务设置，这份文档就是给你看的。

## 启动方式

开发模式：

```bash
pnpm dev
```

然后访问：

- [http://127.0.0.1:5173](http://127.0.0.1:5173)

生产模式下，Console 会由 Polaris Core 直接托管。可通过下面的命令查看当前实际地址：

```bash
pnpm polaris:status
```

或者：

```bash
node packages/cli/dist/bin.cjs console-url
```

Console 会自动发现当前 Polaris Core API 地址，所以即使默认 API 端口被占用，也通常不需要手动改前端配置。

## 主要页面

### 首页

路径：

```text
/
```

主要用于快速了解当前状态：

- Core 是否在线
- 当前代理模式
- 最近请求概况
- 已保存请求数量
- 模拟规则数量
- MCP 是否开启

### 实时请求

路径：

```text
/traffic
```

适合做这些事情：

- 查看实时抓到的请求
- 通过方法、状态码、主机、关键词过滤请求
- 查看请求详情
- 重放请求
- 复制 `curl` 命令
- 将请求带入调试页
- 从请求快速创建模拟规则

### 模拟规则

路径：

```text
/mock
```

适合管理本地模拟规则：

- 创建模拟规则
- 编辑模拟规则
- 启用或停用规则
- 切换场景分组
- 查看规则命中情况

### 调试

路径：

```text
/debug
```

这是一个手动请求调试页，适合：

- 直接发起请求
- 查看返回结果
- 复制 `curl` 命令
- 保存调试请求

### 设置

路径：

```text
/settings
```

这里主要展示：

- 当前代理端口
- API 地址
- MCP 地址
- 代理模式
- 证书状态
- MCP 状态

## 证书下载

在 `Settings` 页和 `Traffic` 页中都可以看到证书相关入口。

证书下载地址会根据当前实际 API 端口生成，而不是写死某一个端口，所以在端口自动切换时仍然可用。

## 端口被占用时会发生什么

Polaris 默认优先使用：

- API：`19601`
- Console 开发端口：`5173`

如果 `19601` 被占用，Core 会自动切换到新的可用端口。Console 会继续自动探测并连接新的 API 地址。

## 常见问题

### 页面打开了，但一直显示连接中

优先检查：

- Polaris 是否已经启动
- `pnpm polaris:status` 返回的健康检查地址是否可访问
- 当前浏览器访问的地址是否来自最新启动结果

### 为什么第二次打开页面更快

因为首页、设置页和部分请求状态会优先读取本地缓存，然后再在后台静默刷新。

### Console 更适合做什么

如果你更习惯可视化操作，而不是直接通过 MCP 或命令行调试，那么 Console 会是最适合的入口。

# 浏览器扩展使用说明

这份文档是写给“想尽快把浏览器接进 Polaris”的人看的。

浏览器扩展本身不是完整工作台，它更像一个快捷控制面板。  
它负责的事情很简单：

- 看 Polaris 是否在线
- 切换代理模式
- 把当前站点加入或移出规则
- 打开 Console

真正看请求详情、保存请求、做 Mock，还是建议去 Web Console。

---

## 先准备什么

你只需要先做两件事：

1. 启动 Polaris
2. 拿到扩展目录

启动 Polaris：

```bash
polaris start
```

查看扩展目录：

```bash
polaris extension-path
```

这个命令会输出一个本地目录，里面就是可以加载到 Chrome / Edge 的扩展产物。

---

## 怎么安装扩展

以 Chrome / Edge 为例：

1. 打开扩展管理页面
2. 开启“开发者模式”
3. 选择“加载已解压的扩展程序”
4. 选择 `polaris extension-path` 输出的目录

如果你是从源码仓库自己构建的，也可以直接加载：

- [apps/extension/dist](../apps/extension/dist)

但对普通使用者来说，更推荐直接用 `polaris extension-path`。

---

## 扩展里几个模式是什么意思

### 直连

浏览器不经过 Polaris。

适合：

- 平时正常上网
- 暂时不想抓请求

### 全局代理

浏览器大部分请求都会走 Polaris。

适合：

- 你想先快速验证 Polaris 是否能抓到请求
- 你想临时观察整个浏览器流量

不适合：

- 你只想代理某一个站点

### 规则代理

只有命中规则的站点才会走 Polaris。

这是最推荐的日常模式。

适合：

- 只代理当前项目站点
- 不影响其他网站
- 联调时更稳、更可控

### 跟随系统

扩展不自己指定代理，交给系统代理设置决定。

适合：

- 你已经有系统级代理方案
- 你只想让浏览器跟系统走

---

## 最推荐的使用方式

如果你平时只是做站点联调，建议直接这样用：

1. 打开目标网站
2. 打开 Polaris 扩展
3. 切到 `规则代理`
4. 点击“仅代理当前站点”或类似按钮
5. 打开 Console 的 `/traffic`

这是最稳、也最不容易影响其他网站的用法。

---

## 关于“当前站点加入规则”的一个重要说明

当前实现里，扩展在你点击“加入当前站点规则”后：

- 会把这个站点写入规则
- 但**不会强制自动切换到 `规则代理`**

如果你当前还在 `直连` 或 `系统`，扩展会提示你：

- 规则已经加上了
- 切到 `规则代理` 后才会真正生效

这样做的好处是：

- 不会突然把你的浏览器代理状态改掉
- 用户更容易理解“加规则”和“启用规则模式”是两件事

---

## 扩展还能做什么

### 打开 Console

扩展可以直接打开本地 Web Console。

### 打开设置页

如果你要看证书、MCP、手机接入说明，直接从扩展跳设置页很方便。

### 打开浏览器证书设置

如果你在做 HTTPS 调试，这个入口会省很多时间。

---

## 为什么它通常能自动连上正确端口

你不需要手动告诉扩展“Core 一定在 19601”。

当前扩展会：

- 优先使用上一次成功连接过的 API 端口
- 如果这个端口不通，再自动扫描一组候选端口

所以即使 Polaris 因为端口冲突换了端口，扩展多数情况下也还能恢复正常。

## 常见问题

### 扩展里显示 Polaris 离线

优先检查：

- `polaris start` 是否已经执行
- 扩展是否是最新加载的版本
- 浏览器里有没有重新加载扩展

### 我已经加了当前站点规则，为什么还是抓不到

优先检查：

- 当前代理模式是不是 `规则代理`
- 页面有没有刷新
- 当前 host 是不是你想抓的站点

### 我应该选全局代理还是规则代理

一般建议：

- 快速试一下能不能抓到请求：先用 `全局代理`
- 平时日常联调：优先用 `规则代理`

### 扩展能不能代替 Console

不能。

扩展适合做“开关”和“入口”，不适合做完整操作。  
看请求详情、保存请求、调试请求、做 Mock，还是去 Console 更顺手。

对应文档：

- [Web Console 使用说明](./console.md)
